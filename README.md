# 凌巽的酒馆 · Lingxun's Tavern

凌巽的个人网站，收录角色设定、连载故事、旅途留影与日常手记。以“龙在人类城镇里的私人酒馆”为视觉背景，结合编辑式排版、书页、相纸与公会记录。

- 网站：[lingxun.me](https://lingxun.me/)
- 仓库：[LingXunFurry/lingxun_web](https://github.com/LingXunFurry/lingxun_web)
- 后台：部署后访问站点的 `/admin`
- 最近更新：[2026-11-02 更新日志](docs/updates/2026-11-02.md)

> 网站内容由数据库和上传目录共同承载。克隆仓库不等于恢复线上网站；角色资料、文章、章节、评论、计数和上传图片需要另行备份、迁移。

## 当前功能

### 首页与角色介绍

- 首屏保留满屏照片轮播，支持上一张、下一张、暂停、播放顺序与进度显示。
- 桌面首页逐幕滚动，快速滚轮不会连续跳过多幕；手机使用自然滚动，不减少内容和主要功能。
- 支持多个角色，当前内容围绕主设定凌巽与雷族角色震烁展开。
- 角色图片与资料沿斜线分区，圆形头像与无框箭头切换，图文同步斜向过渡。
- 物种、职业、活动区域等资料与自定义字段并列展示，详细介绍可后台编辑。
- 主展示图与选择头像独立设置；头像可上传、拖动取景，调整水平位置、垂直位置和缩放，无图角色保留占位。

### 故事集与章节连载

- 首页以固定尺寸的双页故事书展示书名、简介、状态、章节摘目与阅读入口。
- 头像和侧边箭头均可切换故事，书内内容按方向水平移动；手机箭头合并在头像旁边。
- 一部故事在动态列表中保留一个入口，章节拥有独立链接，不用每更新一章就新增一条普通动态。
- 每章支持标识、标题、顺序、正文、草稿与公开发布；目录自动汇总公开章节。
- 阅读页顶部及文末提供目录和上一章、下一章入口，评论归属整部故事。
- 原有整篇故事正文与章节锚点继续可读，不要求全部改成新章节格式。

### 旅途留影

- 响应式照片墙，支持类别与角色筛选。
- 详情灯箱支持上一张、下一张、键盘左右键、Escape 关闭、手机滑动、缩放与保存。
- 展示标题、日期、地点、类别、说明和当前位置，保留缩略图导航。
- 图片懒加载、相邻图片预加载、加载失败反馈与空分类状态。
- 首页三张留影与首屏轮播可在后台分别选择和排序，不用修改源码。

### 手记、同行者与联系

- 动态列表支持关键词和日期筛选，关键词覆盖标题、摘要与标签。
- 动态支持 Markdown、封面、配图、附件、外部链接、置顶与发布状态。
- 评论支持留言 ID、回复和评论点赞，后台可管理可见性。
- 友链支持头像、名称、简介、地址和排序管理。
- 未来行程展示日期、地点、描述与随日期变化的状态。
- “联系凌巽”集中提供联系方式，支持自定义应用图标和外部跳转提示。

### 酒馆暗门与像素小游戏

- 页脚敲门三次可展开暗门，保留访客计数、敲杯计数和后端交互。
- 今日酒单按日期从预设酒单中选择，展示调酒名称及原料；今日委托可抽签，并有连续操作回应。
- 纪念日的日期、中英文标题和暗门相关文案可在后台修改。
- 暗门底部及 404 页面提供可展开的像素跑酷游戏，不会进入页面就自动开始。
- 包含二段踏风、送酒计分、麦酒加分与加速、清风酒牵引、护身酒护盾等玩法。
- 难度随有效游玩时间提升并封顶；手机与电脑共用速度和逻辑更新规则。
- 首次玩法提示、暂停、继续、重开和状态反馈整合在游戏画面内，暂停时切换主题也会更新场景。

### 视觉与加载体验

- 明暗主题、本地中文与英文字体、响应式布局和分层入场动画。
- 首页直接进入或刷新时展示像素角色跑步加载动画，至少播放两秒；站内返回不反复播放。
- 内容准备好后再入场，慢网或失败时给出提示，减少旧内容闪现。
- 支持 `prefers-reduced-motion`，收敛位移和连续动效。
- 403、404、500、503 有对应网站风格的提示页，浏览器页面与 API 错误响应分开处理。

## 后台管理

| 栏目 | 管理内容 |
| --- | --- |
| 首页编排 | 轮播照片、首屏主照片、三张首页留影的选择与排序，跳转对应编辑入口 |
| 旅途留影 / 照片库 | 上传、替换、分类、角色绑定、元数据、可见性与展示用途 |
| 角色介绍 | 资料、自定义字段、详细介绍、主展示图、独立头像与圆形取景 |
| 动态管理 | 普通手记、配图、附件、置顶和发布状态 |
| 故事管理 | 所属角色、故事简介、顺序、连载状态与章节目录 |
| 评论、友链 | 评论可见性、友链头像与跳转资料 |
| 酒馆暗门 | 纪念日标题、日期和对应可编辑内容 |
| 行程 / 联系凌巽 | 行程、联系方式、图标、排序和外部链接 |
| 站点内容 | 分组文案、部分图片与前台位置提示 |
| 图片优化 | 已上传图片的使用位置、体积与优化操作 |
| 安全设置 | 修改后台密码、退出登录 |

上传文件后立即显示持续提示，传输与处理期间锁定相关控件；相同文件的在途重复请求会合并，完成或失败后恢复操作。需要保存的表单仍需保存后生效。

管理员密码以哈希存储。后台默认采用 30 分钟会话窗口，有效后台请求可按规则续期；过期或退出后清除本地登录令牌和密码输入，修改密码会使旧令牌失效。项目没有公开的默认管理员密码，首次启动须自行配置。

## 图片处理

- 新上传的静态图片通过独立进程中的 libvips 顺序缩图，生成 WebP 和适配不同屏幕的展示尺寸，并保留原件。
- 浏览器按展示区域选择合适尺寸；已有图片地址和原始文件不会因生成优化版本而被直接覆盖。
- 支持 JPG、PNG、WebP、GIF；动图保持动画，使用单独的安全限制。
- 静态图片上限为 **50 MiB、1.5 亿像素、单边 30000 像素**；动图上限为 **5 MiB、3600 万像素**。
- 大图在安全范围内自动处理，但并非无限制上传；损坏、格式不支持、超限与处理失败会分别提示。
- Nginx 等反向代理的上传大小和超时也需配合配置，不能只修改应用限制。

实现与素材来源见[图片处理及游戏资源说明](docs/upload-errors-resources.md)。

## 技术栈与结构

| 部分 | 实现 |
| --- | --- |
| 页面与构建 | Astro 6、TypeScript、Tailwind CSS 4、原生 CSS |
| 后台与 API | Python、FastAPI、Uvicorn、SQLAlchemy |
| 数据库 | 生产使用 MySQL，本地可使用 SQLite |
| 图片 | Pillow 检查格式、pyvips / libvips 处理静态大图 |
| 字体 | 本地思源宋体、思源黑体、Cormorant、IBM Plex Mono；游戏使用 Fusion Pixel |
| 游戏 | 基于 T-Rex Runner 核心，本站适配与像素美术、局部 canvas-confetti 反馈 |
| 部署 | Astro 构建静态文件，FastAPI 提供页面与 API，Nginx 反向代理，systemd 管理服务 |

```text
src/components/        首页各幕、导航、故事、文章、暗门与小游戏
src/pages/             首页、画廊、手记、友链、文章入口与错误页
src/lib/               公开内容请求、角色切换、加载、章节与游戏逻辑
src/styles/            主题、布局、排版和装饰样式
public/                本地字体、图标、游戏与加载素材、第三方资源
backend/app/           API、数据库模型、鉴权与图片处理
backend/app/static/admin/  后台页面及交互
backend/uploads/       运行时上传文件，不提交 Git
backend/.image-staging/ 图片处理暂存区，不应对外暴露
sql/                   基础 MySQL 建表脚本
scripts/               字体与素材处理工具
tests/                 前端及交互回归脚本
docs/                  更新日志、部署与资源说明
```

`dist/` 是构建输出，不提交 Git。`backend/.env`、数据库文件、上传文件和本地备份也不随仓库同步。

## 本地运行

需要 Node.js **22.12.0 或更高版本**、npm 和 Python（建议使用 3.12）。生产数据库使用 MySQL；只做本地体验时可选择一个独立 SQLite 文件。

### 1. 安装与配置

```bash
git clone https://github.com/LingXunFurry/lingxun_web.git
cd lingxun_web
npm ci
```

按照[后台启动说明](backend/README.md)创建虚拟环境、安装 `backend/requirements.txt` 并配置 `backend/.env`。示例配置不是生产凭据，管理员密码、数据库连接和 JWT 密钥都要自行填写。

### 2. 构建并预览完整网站

```bash
npm run build
```

随后在 `backend/` 下启动 FastAPI。Windows PowerShell：

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Linux：

```bash
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

打开 [本地前台](http://127.0.0.1:8000/) 和 [本地后台](http://127.0.0.1:8000/admin)。只运行 `npm run build` 或打开 HTML 文件，不会自动启动数据库和 API。

### 3. 前端热更新

保持后端运行，在仓库根目录另开终端：

```bash
npm run dev -- --host 127.0.0.1 --port 4321
```

默认开发入口为 `http://127.0.0.1:4321/`，该端口的前台请求本地 `8000` API。后台仍从 `http://127.0.0.1:8000/admin` 进入。

若更换前后端端口或采用不同域名，设置构建时环境变量 `PUBLIC_API_BASE`，并相应调整 `BACKEND_CORS_ORIGINS`。同域部署通常不需要设置 `PUBLIC_API_BASE`。`npm run preview` 也只是预览静态构建，不包含后端。

## 测试与维护

安装前端依赖后，可运行不依赖浏览器的状态测试：

```bash
node tests/record-transition.cjs
node tests/admin-upload-state.cjs
```

在已安装后端依赖的虚拟环境、`backend/` 目录中运行：

```bash
python -m pip install httpx==0.28.1
python -m unittest discover -p 'test_*.py'
```

`httpx` 用于接口测试，不是运行网站的必需依赖；上述版本与本地验收环境一致。浏览器回归脚本还需要 Playwright 和浏览器；部分脚本依赖指定的本地预览数据或 Windows 路径，运行前应检查脚本及 `PREVIEW_URL`、`PLAYWRIGHT_MODULE` 配置。会创建测试内容的脚本只能连接可丢弃的本地测试库，不能指向生产环境。

忘记后台密码时，通过服务器权限运行交互式[密码重置工具](backend/reset_admin_password.py)，不要把密码写入 Git、命令参数或日志。详见[后台维护说明](backend/README.md)。

## 部署与服务器迁移

完整步骤见[全新服务器部署与迁移清单](docs/deployment.md)。迁移至少包括：

1. 确认新机 SSH 身份、账号、权限、目录、磁盘与内存，不假定旧服务器路径仍存在。
2. 安装构建与运行依赖，配置 MySQL、虚拟环境、Nginx 与 systemd。
3. 备份并恢复数据库、`backend/uploads/` 和必要的环境配置；仅克隆 Git 仓库会缺失运行内容。
4. 在独立目录构建，备份后执行应用启动时的增量表结构检查；MySQL DDL 不能视为可随意事务回滚。
5. 配置域名、HTTPS、上传大小与超时，并检查前台、后台、图片、章节、评论及计数接口。
6. 验收完成后再切换流量，保留旧版本与可核对的回退记录。

应用/静态文件回退与数据库恢复是两件事，不能直接把旧数据库覆盖回去，丢掉发布后新增的文章、留言和图片。
